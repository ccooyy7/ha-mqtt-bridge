# 已知限制与验收范围

这是早期版本的能力边界，不应将离线测试通过理解为现场部署完成。

## 已实现并有离线回归覆盖

- 默认手动空名单不暴露任何实体；排除名单优先。
- 核对实体是否暴露、是否只读、命令是否被允许。
- JSON 和 params 基本格式检查，亮度、位置、百分比风速的数值范围检查。
- 正常命令产生 ack 和服务调用消息；验证失败不进入服务节点。
- 已标记 retained 的命令被拒绝；其他 prefix/site 的命令被忽略。
- 保留可解析的 request_id，状态字段转换，以及生成 Function 的发现、状态和结果路径。

测试执行实际导出的 Function JavaScript，并模拟上下文和消息；不启动完整 Node-RED，也不验证外部节点的运行时兼容性。

## 尚未完成

1. **命令幂等与持久化**：没有重复请求缓存、命令队列或断线重放策略。request_id 仅用于回执关联。
2. **逐设备能力校验**：类型映射不等于能力探测；模式枚举、温度上下限及某些必填参数由服务端校验。
3. **在线状态完整性**：unknown 暂仍显示 online；HA 整体掉线、实体删除时不会主动把所有 retained availability 更新为 offline。
4. **重连立即同步**：MQTT 重连不立即触发全量发现；可手动触发或等待十分钟周期。Broker retained 恢复取决于持久化配置。
5. **retained 清理**：删除实体、改名或改变 Topic 后，旧 retained 数据不会自动清除。
6. **设备存在性预检**：通过命名空间和配置校验后，不存在实体的处理结果依赖具体服务；成功不等于实际设备存在或动作完成。
7. **完整版本矩阵**：尚未逐一验证 HAOS、独立 Node-RED、WebSocket 节点包及各 Broker 版本组合。
8. **单一映射来源**：核心模块与 flow 生成器仍各有映射实现，维护时需同步修改；回归测试覆盖关键行为，不保证每个分支完全等价。
9. **单位与枚举转换**：units 只改单位标签，没有通用数值单位换算和枚举映射框架。

## 配置语义

自动模式的空白名单表示暴露所选类型全部实体；实体级 writable 值优先于 writableDomains。希望强制限制某个实体时应检查两处配置，或使用 entityBlocklist 完全排除。

MQTT 账号的 Broker 权限仍由部署方配置。Function 中的暴露与命令校验不是 Broker ACL 的替代品。导出的实际流程、凭据、设备目录和状态缓存不属于公开仓库内容。

## 现场验收建议

- 新订阅收到 meta/state/availability，确认是预期实体和字段。
- 在 HA 中改变主状态和属性，分别观察 MQTT 更新。
- 对每个实际设备验证允许的命令、枚举、范围和只读拒绝行为。
- 检查非法 JSON、越界参数与不支持命令的 result。
- 分别重启 HA、Node-RED、Broker，检查恢复、状态新鲜度与旧消息。
- 检查灯、开关的多个实体是否对应同一物理回路，避免上层重复控制。

项目自带测试不会执行这些设备动作，也不应作为生产级可靠性认证。
